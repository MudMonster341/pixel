# Interiors plan (P3)

**Status (2026-09-17): built.** Main Block (4 floors), Library Block (2 floors) and Mechanical
Block (2 floors) all have full internal layouts: straight corridors, rectangular rooms, doors,
stairs that line up between floors, and simple furniture per room type. The LUG room and hostel
interiors are intentionally **not** included (owner decision: LUG comes later, hostels are outside
only). No people, no story content -- the owner writes that later.

Generated by `tools/interiors/build-interiors.js` from the data in `tools/interiors/plans.js`
(`npm run interiors`), the same way the campus is generated from `tools/campus/layout.js`. Preview
PNGs (4 px/tile) are in `docs/research/interiors/<key>.png` -- look at those, or the real game, for
the actual layout; the ASCII sketches below are a coarse guide, not pixel-exact.

## Scale and method

- **1 m per tile indoors** (outdoors is 2 m), per the owner's 2026-09-13 decision.
- Every building's floors share **one canvas size** and **one fixed stairwell rectangle**, so
  stairs land in the same place on every floor (checked by
  `tests/unit/interiors.test.js`, "stairs line up between floors").
- Layout engine (`tools/interiors/build-interiors.js`, class `Floor`): a room is an axis-aligned
  rectangle with a 1-tile wall ring (reusing the outdoor `bitsWallPlain`/`bitsWall`/
  `bitsWallEndL`/`bitsWallEndR` tiles, so interiors match the buildings' own outside walls) and a
  floor tile picked by room type. `connect(idA, idB)` finds the wall two rectangles share and
  clears a door-width opening in it -- it throws if they don't actually touch, which is how most of
  the layout bugs below were caught while building this (fixed before committing, not left in).
  Furniture is only ever placed at least one tile in from a room's own walls, so a ring around the
  inside of every room always stays clear: whichever wall a door ends up on, it always connects to
  that ring, and furniture can never wall off part of a room or block a doorway.
- `tools/interiors/layout-helpers.js`: `layoutRow`/`layoutColumn`, pure arithmetic that lays a row
  of same-side rooms edge to edge against a corridor wall, so most rooms are declared as "this
  order, these widths" in `plans.js` rather than by hand-picked coordinates.

## The door/stairs object format

A point object on the `objects` layer of a Tiled map, `type: "door"` or `type: "stairs"`, with
properties:

| Property | Meaning |
|---|---|
| `to` | The target map's key (`src/maps.js`), e.g. `"main-block-g"` or `"campus"` |
| `toId` | The **name** of the door/stairs object to land at, on the target map |
| `facing` | The direction the player faces once they arrive **at this object** (used when something else's `to`/`toId` points here) |

`src/scenes/world.js` resolves these generically (`WorldScene.warpPoints`/`resolveSpawnAt`): landing
at a door/stairs object means standing one tile further along its own `facing`, not on the trigger
tile itself (so you don't immediately re-trigger it walking back). An unknown `to` map logs a
console warning and shows a "Closed for now." toast instead of crashing -- this matters because
campus.json ships three of these (Main/Library/Mechanical Block entrances) that any future,
not-yet-merged campus rebuild also needs to emit in this same shape.

Example (Main Block's outdoor entrance, in `assets/maps/campus.json`, added by
`tools/campus/build-campus.js`):

```json
{ "name": "Main Block entrance", "type": "door", "properties": [
  { "name": "building", "value": "Main Block" },
  { "name": "to", "value": "main-block-g" },
  { "name": "toId", "value": "Main Block Ground Floor entrance" },
  { "name": "facing", "value": "down" }
] }
```

...and its matching interior side, in `assets/maps/main-block-g.json`:

```json
{ "name": "Main Block Ground Floor entrance", "type": "door", "properties": [
  { "name": "to", "value": "campus" },
  { "name": "toId", "value": "Main Block entrance" },
  { "name": "facing", "value": "up" }
] }
```

Stairs objects use the identical shape (`type: "stairs"` instead of `"door"`); a stairwell room
usually holds two of them (an "up" and a "down"), each pointing at the matching object on the
neighbouring floor.

**Outdoor connection (P2 handoff):** the campus rebuild in the main tree isn't merged into this
branch yet, so this branch adds the three entrance doors directly to the *current*
`tools/campus/build-campus.js` (the smallest self-contained change: three extra properties on the
door objects it already emits) so the interiors could be tested end to end. Whoever rebuilds the
campus from OSM (ADR 0009) should emit `door` objects in this exact shape at the Main/Library/
Mechanical Block entrances -- same `to`/`toId`/`facing` properties, any position, and it will work
with no changes on the interiors side.

## Main Block (4 floors)

Real footprint ~115x102 m (OSM way 224330149); the interior is a simplified rectangle, not the L/
notch shape the real building may have, scaled up for a walkable 1 m/tile layout with the number of
real rooms the tour lists. **Canvas: 136x84 tiles**, all 4 floors -- over the ~110x90 target because
fitting every named room (career services, five-office admin hub, an auditorium suite, a six-room
sports hub, ICL+incubation, plus the upper floors' 19 labs, 13 clubs, etc.) in a single-corridor
layout needs the extra length; the corridor itself is what's long, not the building's "footprint" in
a real sense. Every floor shares one straight spine corridor (`x:4-120, y:42-46`) and one stairwell
rectangle (`x:72-79, y:34-42`), attached to the spine's top (north) side on every floor.

**Ground floor** (entrance at the bottom of the Foyer, `main-block-g`):

```
 [Incubation]  [Reception][CareerSvc][Admiss] [Stairs] [AUGSD][Director][DepReg][StudWelf][Telepres]
 [   ICL    ]--------------------------- spine corridor ----------------------------------------
 [MiniMart][Badminton][TableTennis]  [Foyer 2]         [Medical]  [Audi Lobby][Audi]--[Parents Lng]
                       |            [ Foyer  ]                        |
                       |         (entrance, south wall)               (Auditorium, stage at far end)
```

Rooms: Foyer (double-height atrium look: reception desk, sofas, plants, noticeboard) -> Foyer 2 ->
spine corridor -> Reception; Career Services; the Admissions/AUGSD/Director's Office/Deputy
Registrar/Student Welfare hub; the Auditorium (with its Lobby and the Parents-Visitor Lounge, stage
at the south end); the sports hub (Mini Mart, Badminton, Table Tennis -- Prime Medical Centre is
next to the Foyer instead, its own "Doctor's Room" simplified to a curtained bay inside it, there
wasn't room for a fully separate one); Telepresence Classroom; Intelligent Computing Lab +
Incubation Centre. Stairs up + a decorative lift in the stairwell room.

**1st floor** (`main-block-1`): the Connecting Lobby sits directly over the Foyer/Foyer 2 footprint,
with a railing-bordered atrium void punched into its floor so it visually overlooks the real foyer
below. Off the spine: **ICVL** and **Room 195** (docs/STORY.md key rooms, M3 -- renamed 2026-09-22
from two of what were three plain "50 Seater Classroom" rooms; see "Story rooms" below), one more
50-seat + two 60-seat classrooms, the Locker Area, Counselling Centre (+ its Group Session and
Therapy rooms), International Student Services, a Meeting Room and a Guest Meeting Room. Stairs down
to G, up to 2nd.

**2nd floor** (`main-block-2`): department labs off the spine -- EEE (Analog & Digital, Communication
Systems, Electrical Machines, Instrumentation, Power Electronics), CHEM (Chemical Engineering,
Petroleum), CS (Computer Lab, Database Systems, Network & Distributed Systems, Signal Processing),
BIOT (Advanced Molecular Biology, Biotechnology Research, Microbiology), GS (Chemistry -- **Physics
moved to the 3rd floor**, see below), Civil (Soil Mechanics, Transport Engineering), and
Thermo-Fluids -- 18 labs total, the tour doesn't say which floor so this is the sensible guess
("linked from Foyer 2, floor unknown"). Stairs down to 1st, up to 3rd.

**3rd floor** (`main-block-3`): the clubs corridor (ACM, ACM-W, GDG, MTC, IEEE, IFOR, Supernova,
Music, Shades Art, SWE, WIE, Chimera, Student Council), the **Physics Lab** (docs/STORY.md key room,
M3 -- moved here 2026-09-22 from the 2nd floor's GS row, see "Story rooms" below), the Vice
Chancellor Office, Telepresence Conference Room and two guest/meeting rooms. Stairs down to 2nd (top
floor, no further stairs).

## Rough spots and simplifications (read before the owner asks "why...")

- **Building shapes are simplified rectangles**, not the real (possibly L-shaped) footprints -- the
  owner's plan explicitly allows this ("interiors may be scaled/cropped a bit to stay playable").
- **Main Block is 136 tiles wide**, over the ~110 target, because of how many named rooms the real
  tour lists. The corridor is long; no single room is oversized.
- **Prime Medical Centre - Doctor's Room** isn't a separate room on the ground floor plan (space);
  it's a curtained bay inside Prime Medical Centre instead.
- **Which floor a lab/club/office is really on** is mostly a guess for Main Block's 2nd and 3rd
  floors -- the virtual tour doesn't say (see `docs/research/bits-dubai-campus.md` and
  `docs/research/bits-dubai-tour-scenes.json`, "floor unknown"). The Connecting Lobby (1st floor,
  confirmed) and the ground-floor rooms are the only ones with a source for their floor.
- **Furniture is simple by design** (the owner's "empty, furnished simply" decision): one or two
  pieces per type, repeated in a grid, not hand-decorated per room.
- **The lift is decorative only** -- it doesn't warp anywhere, per the ground-floor plan's "stairs +
  a lift tile."
- **The three campus door objects live in the current (pre-ADR-0009) `build-campus.js`**, added in
  the smallest possible diff so this branch could be tested end to end; see "Outdoor connection"
  above for what the campus rebuild needs to emit to keep working with no changes here.

## Tests

- `tests/unit/interiors.test.js`: the committed maps match the generator; every floor is axis-aligned
  (no diagonal-only wall joins, reusing the campus's FB-0009 check); every room and every door/stairs
  object is reachable from that floor's spawn; every door/stairs object's target map + object exists,
  is walkable, and links back; stairs line up between floors of the same building (by comparing the
  stairwell room's rect, not an individual up/down object's point); every room has a named `area`
  object; every map is `indoors: true`. A cross-floor flood fill (following stairs) also checks every
  room in a building is reachable from that building's ground-floor entrance.
- `tests/e2e/interiors.spec.js`: walks from the campus into the Main Block, confirms Shift does
  nothing (FB-0017), takes the stairs up to the 1st floor and back down, and walks back out onto the
  campus in front of the Main Block; the same quick in/out for the Library Block.
- `tests/e2e/campus.spec.js`'s existing "walk from the Gate 2 spawn to the Main Block entrance" test
  now expects the player to actually arrive inside (`main-block-g`), since the door isn't a dead end
